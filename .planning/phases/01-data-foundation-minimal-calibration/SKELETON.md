# SKELETON.md — 行走骨架架构契约

> 本文件记录阶段 1 走通"行走骨架"(从真实照片到第一个基线内参的最小完整链)时
> 定下的架构决策,作为后续所有阶段的契约:后续阶段在这些决策的框架内填充实现,
> 不推翻、不重新争论——除非有数据证明决策本身错了,那时先改这里、再改代码。

## 一、端到端贯通的能力

**一句话:在真实照片上,一条命令接力完成「入库清单 → 双检测器角点 → 2×2 基线内参」,
产物全部带血缘落盘,换数据集只换 input_data 目录内容与 config,不改一行代码。**

这条链已经在真实数据上验证过两次:全量(705 张:640 训练 + 65 测试)与
冒烟测试里的缩小版(3 姿态 × 8 连拍 + 5 张测试,独立进程三命令接力,
见 tests/test_smoke_realdata.py)。全链第一手结论:2×2 = 4 个基线在真实
train 数据上全部收敛,KB4(等距投影鱼眼模型)比针孔+畸变更贴合这批广角数据
(sb_fisheye 整体重投影 RMS 0.083 像素,为四组合最优)。

## 二、架构决策

| 决策点 | 定下来的做法 | 一句话理由 |
|--------|-------------|-----------|
| 运行时 | Python 3.12(钉在 .python-version,防 uv 自动选更新版本)+ uv 锁定依赖(uv.lock 进 git) | 数值工具要可复现:解释器、依赖版本全锁定 |
| CLI 框架 | typer,九个子命令:`calib ingest / corners / noise / calibrate / fisher / evaluate / analyze / report / run-all`,帮助文字全通俗中文,`calib --help` 即流水线地图(D-11/D-13);命令行不收算法参数(D-12) | 命令名 = 流水线阶段名,参数唯一来源是 config,结果可追溯 |
| 数学库 | OpenCV 4.14(锁 <5.0)+ numpy 2.5 + scipy 1.18(成对锁定;scipy 本阶段只入锁未使用) | 四个候选相机模型 OpenCV 原生覆盖;5.0 刚发布,数值可审计性优先,等 5.x 攒几个补丁版再说 |
| 产物仓库 | 每阶段写 `output/<阶段>/run_<UTC时间戳>/`,同一阶段重跑互不覆盖;JSON + npz 落盘,**文件是唯一真相源**,阶段间只靠文件通信 | 每轮留痕、跨轮可比(迭代回环 D-04 的地基),任何环节可独立重跑 |
| 血缘指纹 | `src/calib/util/lineage.py`:每个产物写盘前记「生成时间 / 包版本 / 配置文件指纹(sha256) / 上游产物指纹 / 本轮标识」;下游产物显式记上游文件路径 + 指纹(如 calibration.json 记 corners_file + corners_sha256) | sha256 是内容指纹——内容差一个字节指纹就完全不同,"指纹相同 = 内容相同"的铁证,篡改必显形 |
| 模块布局 | `src/calib/{io, corners, models, solve, evaluation, analysis, visualization, report, util, cli}` 与流水线阶段一一对应(models / evaluation / analysis / report 本阶段仅空壳占位) | 看目录名就知道代码管哪一步;后续阶段只填实现不动结构 |
| 参数唯一来源 | `config/board.yaml`(棋盘规格)+ `config/calibration.yaml`(全部算法参数默认值 + 人工剔除清单 exclude_images);剔除永远是逻辑剔除,input_data 只读(D-03) | 人工审阅后改配置重跑即完成一轮迭代,git 可 diff,谁剔了什么可审计 |
| 剔除与标记的分界 | 入库体检只标记不剔除(D-01);剔除只发生在标定命令的读数据环节(按 exclude_images 过滤,名单进产物血缘) | 职责不混:体检管"发现可疑",标定管"要不要用" |

## 三、骨架已触碰的栈

- **项目脚手架**:pyproject.toml + uv.lock + pytest(含 integration 标记)+ ruff;
- **CLI 全地图**:九个子命令全部就位,其中 ingest / corners / calibrate 已是完整实现,
  其余为计划内占位(打印"由后续阶段实现");
- **真实数据读入与产物写出(带血缘)**:input_data 只读扫描、统一分辨率校验、
  manifest 写盘;角点 npz(未检出帧 NaN 占行不消失)、detection_summary.json、
  calibration.json + residuals.npz、comparison.json;
- **标定数值链**:双检测器(经典 + SB)→ 角点排序规范化 → 按实测方格像素边长
  比例推导亚像素窗口(逐帧断言 2w+1 < 方格边长)→ 2×2 基线求解(针孔用
  calibrateCameraExtended;鱼眼 KB4 用 fisheye.calibrate,失败记录不崩)→
  残差回代落盘。

## 四、本骨架刻意不做的事

列表在此,防止后续阶段重新争论本阶段的极简性:

- **入库体检的判定逻辑与存疑原图副本**(阶段 1 计划 01-04):manifest 已预留
  precheck 字段位,骨架阶段不填;
- **全量角点标记副本与汇总拼图**(阶段 1 计划 01-05):可视化参数已在 config
  就位,骨架阶段一张图都不画;
- **模型层 M1–M4 与双求解后端(OpenCV 对照自写 scipy 求解器)**(Phase 2):
  骨架阶段的 2×2 基线只是"现成函数直接调",不含自写求解器、不含模型注册表;
- **噪声底实测、Fisher 信息/CRLB 理论极限、防作弊评估、误差归因、证据链报告**
  (Phase 3–6):对应五个占位命令,骨架阶段一个都不实现。

## 五、后续切片计划

按 ROADMAP 顺序,每片都建立在本骨架的契约之上:

1. **阶段 1 收尾(01-04 / 01-05)**:入库体检(模糊/曝光/棋盘可见性三指标、
   只标记不剔除)+ 全量角点标记副本与汇总拼图——补齐人工审阅迭代的眼睛;
2. **Phase 2 模型层 + 双求解后端**:M1–M4 模型注册表、自写 scipy 求解器与
   OpenCV 结果对照(多求解器对比本身就是交付物)、解析雅可比(一种"变化率"
   的数学表,用于算参数精度)与数值对照;
3. **Phase 3 噪声底 + Fisher/CRLB**:连拍相减实测噪声底,Fisher 信息
   (衡量"数据对参数有多敏感"的数学量)预测可达精度上界——标定前就知道
   这批数据最好能做到什么程度;
4. **Phase 4–6**:防作弊评估(留出考试/换分组复测/逐帧抽查)→ 误差归因
   (实际 vs 理论极限差在哪)→ 证据链报告汇总。
