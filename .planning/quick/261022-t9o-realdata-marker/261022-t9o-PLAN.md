# 任务目标

测试套件分两档:白天快速档 + 夜间全量档。给 6 个真数据测试文件(共 47 个用例,每个文件要跑十几分钟)打 `realdata` 标记,白天用 `-m "not realdata"` 只跑纯单元测试,夜间命令不变跑全量。

**不改动任何生产代码;不改既有测试逻辑,只加标记。**

## 现状(已勘察,执行者无需再探)

- pytest 配置在 `pyproject.toml` 第 45–51 行 `[tool.pytest.ini_options]`,`markers` 列表已注册 `integration`(无 pytest.ini / setup.cfg / tox.ini)。
- 6 个真数据文件**都已有模块级 `pytestmark = pytest.mark.integration`**(行号:analysis 43 / evaluation 54 / fisher 45 / noise 41 / optimizer 45 / smoke 48)。所以要改成**列表形式**叠加新标记,不能覆盖旧标记——另有 3 个文件(test_corners / test_calibrate_matrix / test_noise_injection)用函数级 `@pytest.mark.integration`,既有 `-m "not integration"` 合并前全量流程必须继续有效。
- 用例数(已用 `--collect-only` 实测):analysis 14、evaluation 11、fisher 7、noise 5、optimizer 6、smoke 4,合计 47;全量套件 605,快速档应为 605 − 47 = **558**。

# 验证小节(全部只用 --collect-only,严禁真跑 realdata 测试)

```bash
# 1) 夜间全量档:应收集 605
uv run pytest tests --collect-only -q 2>/dev/null | tail -1

# 2) 白天快速档:应收集 558(605 减去 6 个真数据文件的 47 个)
uv run pytest tests -m "not realdata" --collect-only -q 2>/dev/null | tail -1

# 3) realdata 档本身:应收集 47
uv run pytest tests -m "realdata" --collect-only -q 2>/dev/null | tail -1
```

逐文件基数(核对任务 2 是否一个文件不漏):analysis 14、evaluation 11、fisher 7、noise 5、optimizer 6、smoke 4。若 2) 与 3) 之和 ≠ 1),说明有文件漏打标记或标记名写错。另确认 3) 不产生 `PytestUnknownMarkWarning`(标记已注册)。

# 注意事项

- **禁止真的运行 realdata 测试(连一条都不行)**:后台正在跑全量套件,机器负载 14+,真数据用例本身就是十几分钟级的最小二乘解算 + joblib 并行,再跑会互相拖死,且可能污染落盘产物轮次。验证一律用 `--collect-only`(只收集不执行,实测 6 文件收集仅需约 1.6 秒)。
- 标记必须是**叠加**不是替换:删掉 integration 会改变既有 `-m "not integration"` 行为,破坏"合并前跑全量"流程。
- 白天快速档命令口径:`uv run pytest tests -q -m "not realdata"`;夜间全量档命令不变:`uv run pytest tests -q`。
- 全部新增注释/说明用通俗中文,不堆行话。
